# Golden v2 — Out-of-Sample-Messung + Audit-Topf (THE-430) Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** Den In-Sample-Vorbehalt der Gate-2-Zahlen auflösen (frischer, unabhängig adjudizierter Prüfsatz über ALLE Korpus-Quellen) und die 22 Verdachtsfälle auf normKind/bindingness auditieren.

**Mess-Disziplin (hart):** `TYPING_PROMPT_VERSION` bleibt bis zur v2-Messung auf **tp-2 eingefroren**. Reihenfolge: v2 bauen → Cross-House labeln (Opus + GPT-5) → 🧑 Adjudikation → Freeze → **dann** tp-2 messen = die ehrliche Generalisierungs-Zahl. Neue Präzedenzen aus der v2-Adjudikation fließen erst DANACH in tp-3 (gemessen an künftigem v3). Ratsche gegen In-Sample-Argumente.

**Zwei Töpfe, getrennt gebaut + berichtet:**
| Topf | Datei | Inhalt | Misst |
|---|---|---|---|
| Frisch | `typing.v2.draft.json` → `typing.v2.json` | ~70 Fälle, disjunkt zu v1, gestreut über ALLE Quellen (inkl. MDR/PSD2/eIDAS/ePrivacy/Data Act) | Generalisierung |
| Audit | `typing.v2-audit.draft.json` → `typing.v2-audit.json` | die 22 Verdachtsfälle (typing.normKind ≠ legislation ∨ typing.bindingness ≠ binding) | Fehler-Audit der zwei Achsen |

Audit getrennt, weil über Modell-Ausgabe selektiert (Selektions-Bias) — darf die Generalisierungs-Zahl nicht verunreinigen.

**Erwartung dokumentiert:** partyRole sinkt vermutlich out-of-sample (neue Regime ohne Rollen: PSD2-Zahlungsdienstleister, eIDAS-Vertrauensdiensteanbieter → per Rubrik n/a bzw. Streit). Das ist Befund, nicht Scheitern; Facetten-Erweiterung 1.7.0 erst NACH Messung (Gate-1-Muster).
