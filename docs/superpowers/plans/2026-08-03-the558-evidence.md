# THE-558: Evidence-Objekt — Implementierungsplan (kompakt)

> **For agentic workers:** REQUIRED: Use superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Nachweise als append-only Verweise mit Hash und Textstand-Alterung; `attested` verlangt frische Evidenz und fällt bei Novelle mit sichtbarem Grund zurück.

**Architecture:** `Evidence`-Modell nach WORM-Muster (THE-445) + Version-Lock-Feldern (THE-306, identisch zum Mapping); reine Regel-Funktionen; Evidence-Pass in der bestehenden Drift-Schleife (`regulationDrift.service.ts`); Guard in der Notar-Route aus THE-557.

**RVTM:** `docs/superpowers/rvtm/2026-08-03-the558-evidence-rvtm.md` · **Ticket:** THE-558 (Slice 2 von THE-552)

**Entscheidungen (Entscheider 2026-08-03):** Verweis + Hash, kein Upload · `kind` bleibt **Freitext** bis THE-553 den Werteraum bottom-up liefert (kein zweiter Katalog am API-Rand).

## Tasks

### Task 1: Reine Regeln + Modell
- Create `packages/server/src/services/evidence.service.ts`: `assertAppendOnly`, `refCarriesCredentialMaterial`, `isFreshEvidence`, `resetAttestedForStale(gates)` (attested→unknown mit Grund „evidence went stale (law text changed)"; nur wenn attested=yes).
- Create `packages/server/src/models/Evidence.ts`: `projectId`+`requirementId` (indiziert), `kind` (Freitext, min 1), `ref` (mit Credential-Guard als Validator), `sha256` (`/^[0-9a-f]{64}$/i`), `collectedAt`, `collectedBy`, `regulationKey?`, `regulationVersionHash?`, `stale` (default false), `supersedes?`; WORM `pre('save')` über `assertAppendOnly`.
- Test `packages/server/src/__tests__/evidence.test.ts` — TDD rot zuerst: WORM-Helper, Credential-Guard (Bearer/`token=`/`user:pass@`/`ta_`-Key), sha256-Format, `resetAttestedForStale` (yes→unknown mit Grund; unknown/no bleiben), Modell-`validateSync`.

### Task 2: Routen + attested-Guard
- `requirements.routes.ts`: `POST /:projectId/requirements/:id/evidence` (`collectedBy` aus Session, Zod ohne dieses Feld; `supersedes` markiert Vorgänger `stale` NICHT — er bleibt lesbar, nur der neue zählt), `GET …/evidence` (Liste, neueste zuerst).
- Gates-Route: `gate==='attested' && state==='yes'` → mindestens eine Evidenz mit `stale !== true` für dieses Requirement, sonst **400** mit benanntem Grund (THE-558).
- Client `RequirementsForElementSection.tsx`: Toast zeigt die **Server-Begründung** statt eines generischen Texts.

### Task 3: Drift-Pass (Alterung)
- `regulationDrift.service.ts`: zweiter Pass über `Evidence` mit `regulationKey`+`regulationVersionHash` — Hash-Abweichung ⇒ `stale: true` (Bericht zählt `evidenceStaled`). Danach: betroffene Requirements mit `attested.state==='yes'` und **null** frischen Evidenzen ⇒ `gates.attested = resetAttestedForStale(...)` (Bericht zählt `attestedReset`). Nichts wird gelöscht.
